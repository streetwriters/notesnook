# Help documentation coverage audit

Notesnook **3.4.x** · help site **90 pages** · last run 2026-07-28.

This is the post-rewrite state. The first run (63 pages) found 14 feature areas with no page at all, 9 pages with factual errors and 10 that were incomplete; the second run re-checked all of it and swept the app again for anything missed. Method throughout: parallel source scans required to cite `file:line`, then an adversarial fact-check whose job was to disprove claims rather than confirm them.

## Source bugs — fixed

All four app-side bugs this audit surfaced have been fixed in the app and the docs regenerated against them:

| Bug | Was | Now |
| --- | --- | --- |
| `strings.none()` | returned `"Cell border width"` | `None` |
| `strings.alignCenter()` | returned `"Alignment"` | `Align center` |
| `sinkListItem` keybinding | `Mod-Shift-Down`, bound to nothing | `Tab` |
| Font-size shortcuts | labels inverted vs handlers | `Ctrl+[` increases, `Ctrl+]` decreases |

`keyboard-shortcuts.md` was regenerated and now reads `Sink list item | Tab`.

One display nuance remains: `formatKey` maps any `ctrl` to `⌘` on macOS (`keybindings.ts:487-489`), but the font-size bindings are literal `Ctrl-[` / `Ctrl-]`, which in ProseMirror means Control even on a Mac. The generated page's Mac column therefore shows `⌘ [` for a shortcut that fires on Control. Fix by binding them as `Mod-` or by not macifying a literal `Ctrl-`.

## Historical: the error that could not be fixed in the docs

`keyboard-shortcuts.md` is generated by `scripts/document-keyboard-shortcuts.mjs` from `packages/common/src/utils/keybindings.ts`, and the registry itself is wrong in two places. Both are also wrong in the app's own shortcuts dialog:

1. **Font size keys are inverted.** `keybindings.ts:212-223` labels `Ctrl+[` "Increase font size" and `Ctrl+]` "Decrease font size". `packages/editor/src/extensions/font-size/font-size.ts:90-105` binds the opposite. The Mac column also renders `⌘ [` although the binding is literally `Ctrl-[`.
2. **`sinkListItem` is registered as `Mod-Shift-Down`** (`keybindings.ts:170`), which nothing binds. The real key is `Tab` (`check-list-item.ts:102`, `outline-list-item.ts:121`).

A third, related app-side string bug: `strings.alignCenter()` returns `"Alignment"` — the real "Align center" line is commented out (`strings.ts:2292`) — so the image and embed centering buttons' tooltips read "Alignment".

Fixing these three is a small source change plus a regeneration of the page. Until then the generated page repeats the registry's errors.

## Third verification round (2026-07-28)

A full re-review matched every documented claim against the 3.4.x source: a mechanical sweep by me (588 quoted UI labels, 6 settings paths, 32 keyboard shortcuts, 32 plan tags) plus three adversarial agent passes over the sections that had not been independently checked.

Fixed: 13 label mismatches (`Privacy & security`, `Redeem gift code`, `Pin notification`, `Backup & restore`, the four server names, …) and ~20 further factual errors — Export CSV documented in the wrong menu, mobile table settings, the Android snooze action, `Unpin notification`, the iOS widget's name and description, regional pricing over-attributed to Pro, bulk **PDF export works on mobile** (it is only single-note on web/desktop), `Biometric unlocking`, "hide note title" affecting the tab title rather than the task switcher, three markdown-shortcut table rows, and the mobile Inbox API paths.

Two structural problems surfaced from the importer package (`@notesnook-importer/core@2.4.5`, pinned in `apps/web/node_modules`):

1. **Standard Notes is no longer a selectable importer.** `standard-notes/` still exists as files but is not registered in `provider-factory.js`, so it cannot appear in the app's dropdown. The page now carries a warning and routes people through the Markdown/plaintext importers instead; it was removed from the hub table and FAQ. Whether to retire the page is a product decision.
2. **Two live providers had no page, and the app linked to those missing pages.** `Fusebase (formerly Nimbus Note)` and `TextBundle` both set `helpLink` to `help.notesnook.com/importing-notes/import-notes-from-fusebase` and `…-from-textbundle-files`, which 404'd. Both pages now exist at exactly those slugs.

Claims that remain unverifiable in this repo, and need a product answer: the 5-year plan's 30-day trial (Paddle-served), the monograph 15 MB limit, the Inbox API's 10 MB body cap and 60 req/min rate limit (all server-side), whether links-and-embeds gating in monographs is enforced anywhere client-side, and the per-provider "supported formats" checklists that depend on the external importer package.

## Notes for whoever writes here next

- `docs/help/STYLE.md` is the contract: verification requirement, plan tags, platform tabs, SEO frontmatter, linking clusters.
- Plan tiers come from `packages/common/src/utils/is-feature-available.ts` and nowhere else. All 35 gated features are monotonic across tiers, so "Pro includes Essential" is provably true.
- Where `keybindings.ts` and an editor extension disagree about a shortcut, the extension wins.
- `contents/v<version>/` is generated build output. Never edit it; edit the root copy, and use `npm run docs:fork` to preserve old text for an archived version.
